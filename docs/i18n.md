# Sistema de Internacionalización (i18n) — Zenith Dash

Adaptación a React + Vite del sistema documentado en
`task-app/user-web-portal/docs/i18n.md`. Sin dependencias externas:
contexto de React + diccionarios empaquetados.

## 1. Arquitectura

```
TopbarLocale (ES/EN con banderas)
  └─ setLocale('es' | 'en')
  └─ LocaleProvider persiste en localStorage["zenith-dash:locale"]
  └─ <html lang> sincronizado
  └─ useLocale().t(key, vars) re-renderiza todo al instante (sin recarga)
```

Pilares:

1. **Diccionarios**: `shared/i18n/es.ts` (fuente de verdad), `en.ts`, `pt.ts`,
   `fr.ts`, `it.ts` y `de.ts` con exactamente la misma estructura de llaves,
   por módulo (`nav`, `topbar`, `search`, `notifications`, `blank`, `locale`,
   `ui`). `shared/i18n/i18n.parity.ts` rompe la compilación si una llave
   falta en algún idioma.
2. **Estado global**: `LocaleContext` (`shared/components/locale/`) con
   `useLocale()` (`shared/hooks/useLocale.ts`).
3. **Traducción**: `t("topbar.createEvent", { query })` — notación por puntos,
   interpolación `{var}`, fallback a `es` y luego a la llave (aviso en consola
   solo en DEV).
4. **Mocks con llaves**: los mocks guardan `labelKey`/`titleKey`/etc., nunca
   texto; los componentes resuelven con `t()` al renderizar (el filtrado de
   búsqueda también usa `t`, por eso filtra en el idioma activo).

## 2. Cómo traducir un componente nuevo

1. Agrega las llaves en `es.ts` y su espejo en `en.ts`.
2. Usa `const { t } = useLocale();` y reemplaza los textos por `t("...")`.
3. Nombres propios, emails, rutas, valores de demo y tokens técnicos
   (⌘K, kbd, códigos) no se traducen.

## 3. Reglas de oro

1. Nunca textos duros en JSX visible (incluye `title`, `aria-label`,
   `placeholder` y `alt`).
2. Paridad es/en: toda llave agregada en `es.ts` existe en `en.ts`.
3. Notación por puntos (`nav.manageEvents`); interpolación `{var}`.
4. Probar ambos idiomas antes de dar por terminado.
