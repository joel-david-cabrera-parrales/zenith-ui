# Internacionalización en React: guía paso a paso

Esta guía explica cómo añadir selección de idioma a una aplicación React sin una biblioteca de traducción. Usa diccionarios JSON, un contexto de React y una función `t()` con claves anidadas e interpolación.

En este repositorio la implementación está en `zenith-react/src/shared/`: cuatro diccionarios (`es`, `en`, `fr`, `de`), `LanguageProvider`, los hooks `useLanguage`/`useTranslation` y un selector en la barra superior.

## 1. Decide los idiomas y las claves

Antes de crear componentes, define:

- Los idiomas disponibles y cuál se usa por defecto.
- El formato de las claves: por ejemplo, `pages.auth.login.title`.
- Cómo se guardará la selección del usuario.
- Qué hacer cuando falta una traducción.

Mantén la misma estructura en todos los diccionarios. Es más fácil encontrar y validar una clave que tiene la misma ruta en cada idioma.

## 2. Crea los diccionarios

Puedes organizar las traducciones en archivos JSON anidados por área o página:

```json
{
  "common": {
    "save": "Guardar",
    "welcome": "Hola, {{name}}"
  },
  "pages": {
    "profile": {
      "title": "Tu perfil"
    }
  }
}
```

Crea una copia con los mismos nombres de claves para cada idioma:

```text
src/i18n/
├── es.json
├── en.json
└── fr.json
```

Las claves que se leen desde la aplicación deben resolver a texto. Si necesitas listas, crea claves independientes para cada elemento o amplía el traductor para admitir arrays.

## 3. Define los idiomas y persiste la selección

Usa un tipo unión para evitar códigos de idioma inválidos. Encapsula el acceso a `localStorage` para poder cambiar la clave y el idioma por defecto en un único lugar:

```ts
export const LANGUAGES = ['es', 'en', 'fr'] as const;
export type AppLanguage = (typeof LANGUAGES)[number];

const STORAGE_KEY = 'my-app:language';
const DEFAULT_LANGUAGE: AppLanguage = 'es';

export function getStoredLanguage(): AppLanguage {
  try {
    const value = window.localStorage.getItem(STORAGE_KEY);
    if (value && LANGUAGES.includes(value as AppLanguage)) {
      return value as AppLanguage;
    }
  } catch {
    // El almacenamiento puede estar deshabilitado; continúa con el idioma por defecto.
  }
  return DEFAULT_LANGUAGE;
}
```

En una aplicación con renderizado en servidor, protege también las lecturas de `window` con una comprobación `typeof window !== 'undefined'`.

En Zenith UI los códigos son `es | en | fr | de`, el idioma por defecto es inglés y la clave de almacenamiento es `zenith-ui:language`.

## 4. Crea el contexto y el proveedor

El proveedor mantiene el idioma activo y entrega tres operaciones a la aplicación: leer el idioma, cambiarlo y traducir una clave.

```tsx
interface LanguageContextValue {
  language: AppLanguage;
  setLanguage: (language: AppLanguage) => void;
  t: (key: string, params?: Record<string, string | number>) => string;
}
```

El traductor debe recorrer la clave separada por puntos y sustituir los parámetros:

```ts
const lookup = (dictionary: Record<string, unknown>, key: string): string | null => {
  let value: unknown = dictionary;

  for (const part of key.split('.')) {
    if (!value || typeof value !== 'object' || !(part in value)) return null;
    value = (value as Record<string, unknown>)[part];
  }

  return typeof value === 'string' ? value : null;
};

const translate = (key: string, params?: Record<string, string | number>) => {
  const template = lookup(dictionaries[language], key) ?? key;
  return template.replace(/\{\{(\w+)\}\}/g, (match, name: string) => {
    const value = params?.[name];
    return value === undefined ? match : String(value);
  });
};
```

La expresión `?? key` muestra la propia clave cuando no hay traducción; por eso una interfaz puede llegar a mostrar textos como `pages.profile.title`. Esto ayuda a detectar faltantes durante el desarrollo, pero no sustituye la comprobación de paridad entre diccionarios.

En `LanguageProvider`, inicializa el estado con `getStoredLanguage()` y guarda cada cambio:

```tsx
const [language, setLanguage] = useState<AppLanguage>(() => getStoredLanguage());

useEffect(() => {
  try {
    window.localStorage.setItem(STORAGE_KEY, language);
  } catch {
    // La aplicación sigue funcionando si no se puede persistir la preferencia.
  }
}, [language]);
```

Añade un hook (`useLanguage`) que lea el contexto y falle con un mensaje claro si se usa fuera del proveedor. Si prefieres una API pequeña en los componentes, crea además un hook `useTranslation()` que exponga solo `t`.

## 5. Monta el proveedor en la raíz

Envuelve el router una sola vez, cerca de `createRoot`, para que el selector y todas las páginas compartan el mismo estado:

```tsx
createRoot(document.getElementById('root')!).render(
  <LanguageProvider>
    <App />
  </LanguageProvider>,
);
```

En Zenith UI se monta desde `src/main.tsx`, junto al `ThemeProvider`.

## 6. Traduce el contenido de los componentes

Usa `t()` para todo texto visible, incluidos títulos, botones, placeholders y nombres accesibles:

```tsx
const { t } = useTranslation();

return (
  <form>
    <h1>{t('pages.profile.title')}</h1>
    <button type="submit">{t('common.save')}</button>
    <p>{t('common.welcome', { name: user.name })}</p>
  </form>
);
```

La traducción contiene `"welcome": "Hola, {{name}}"`. En el proveedor de este proyecto se usa doble llave para interpolar (`{{name}}`). Las rutas, nombres propios y tokens de código suelen permanecer sin traducir; decide esa convención para el producto y aplícala de forma consistente.

## 7. Añade un selector de idioma

El selector solo necesita leer el idioma actual y llamar a `setLanguage` al elegir otra opción:

```tsx
const { language, setLanguage } = useLanguage();

<select
  value={language}
  onChange={(event) => setLanguage(event.target.value as AppLanguage)}
  aria-label="Seleccionar idioma"
>
  <option value="es">Español</option>
  <option value="en">English</option>
  <option value="fr">Français</option>
</select>
```

Una lista exportada de opciones evita duplicar códigos y etiquetas. Zenith UI ofrece un selector con filtro, estado seleccionado y cierre con Escape en `shared/components/topbar/LanguageSelect.tsx`.

## 8. Añade un idioma nuevo

1. Agrega su código al tipo `AppLanguage` y al validador de almacenamiento.
2. Crea el diccionario con la misma estructura de claves.
3. Registra el diccionario en `LanguageProvider`.
4. Añade la opción al selector.
5. Recorre cada ruta y valida textos, placeholders, tooltips y mensajes de estado.

No basta con que TypeScript compile: como los diccionarios se resuelven en tiempo de ejecución, la compilación no detecta por sí sola una clave ausente. Compara recursivamente las claves de los idiomas o crea una prueba de paridad.

## 9. Verifica el resultado

- Cambia el idioma y confirma que la página se actualiza sin recargar.
- Recarga y comprueba que se conserva la selección.
- Busca claves visibles en la interfaz; si aparece una ruta de traducción, falta una entrada o el nombre no coincide.
- Comprueba textos largos, saltos de línea y etiquetas accesibles en todos los idiomas.
- Ejecuta `npm run lint` y `npm run build` desde `zenith-react`.
